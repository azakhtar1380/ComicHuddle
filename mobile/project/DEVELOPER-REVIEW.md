# ComicHuddle developer readiness review

Reviewed 9 October 2026. Website source: `/workspace/sites/panelry`. Native Expo source: `/workspace/scratch/45922a1a6a9c/ComicHuddle-App`. The approved comic theme, six mobile tabs, Comic Workshop label and account drawer focus fix were preserved. This review distinguishes source and isolated integration checks from live browser/device verification.

## Changes completed

- **Private photos:** Public listing, showcase, trade-pile and provider photos now respect visibility, moderation and either-direction collector blocks. Photo responses and API errors use `private, no-store`. Participants retain access to their existing private care-condition records after blocking, while outsiders cannot fetch them.
- **Uploads:** The server enforces streamed byte limits, recognized still-image container structure, a 4,800-pixel maximum edge and 16-megapixel cap. JPEG EXIF/XMP/IPTC/comments are removed across all scans, including progressive scan boundaries. PNG EXIF/text/time chunks and WebP EXIF/XMP are removed. Animated PNG/WebP containers are rejected. This bounded parser does not claim to fully decode or certify an image.
- **Collection integrity:** Empty/duplicate copy IDs, duplicate wants, duplicate trade IDs and references to missing owned copies are rejected. Ownership checks for photo references use bounded chunks.
- **Concurrent collection edits:** GET returns an opaque quoted ETag. POST requires its matching `If-Match` value; missing versions return 428, stale versions return 409. D1 compare-and-swap updates ensure that two concurrent saves cannot silently overwrite each other. Legacy saved collections receive stable version tokens without rewriting their content.
- **Abuse controls:** Authenticated writes use persistent D1 minute, day and action counters incremented atomically across requests. Throttles return 429 and `Retry-After`. Counter maintenance removes at most 100 expired records on each subsequent authenticated write.
- **Reports:** A collector can report only existing content they are entitled to see: their own conversations, joined-group posts, visible unblocked profiles/listings/providers/reviews. Arbitrary message IDs, inaccessible posts and nonexistent content are rejected.
- **Marketplace state:** Listing withdrawal closes pending offers. Offer insertion is conditional on a currently active listing, and offer responses atomically require both a pending offer and an active owned listing. Unconnected checkout continues to create no payment or order.
- **Moderation:** Owner restrictions persist separately from public profiles, preventing both edits and delete/recreate flows from bypassing moderation. Provider restrictions also survive profile deletion. Export, account deletion and existing care custody access remain available. Owner-only restoration clears restrictions without automatically republishing hidden profiles or studios.
- **Consent:** Profile creation and legacy profile updates require an explicit acknowledgement. Server-versioned consent receipts record only real `accept: true` submissions; existing current receipts are preserved otherwise. Receipts are visible only to the account owner and included in account export. Deleting the application profile removes its receipt.
- **Account export:** An authenticated download includes only the user's owned or participated records: private collection, profile and receipt, uploaded-photo metadata, listings, offers, authored posts, memberships/groups, conversations/messages, blocks/swipes/reports, studio, reviews, private care jobs/events and retained security metadata.
- **Request handling:** Account mutations read bounded UTF-8 streams and reject null, arrays, primitives or malformed JSON with controlled 400 responses. Missing storage/database services produce controlled errors rather than accidental details.
- **Read aggregation:** Social profile, collection, provider, membership/count and latest-message queries are batched into per-request maps. Comic Workshop uses grouped rating statistics and bounded people/provider lookups. ID batches are at most 64; two-sided block lookups use 32 IDs to stay within the total parameter bound. Private care media checks use participant-restricted JSON existence queries rather than loading entire custody histories.

## Migration and compatibility

`drizzle/0005_public_readiness.sql` adds the collection revision token, profile moderation and consent fields, provider moderation field, `write_limits` and `account_restrictions`. Empty defaults preserve legacy rows and do not invent old consent. The journal and `0005_snapshot.json` match `db/schema.ts`; Drizzle reports no further schema changes to migrate. Existing successful API shapes remain compatible except for the intentional version precondition on collection writes, which the web client now supplies.

## Verified checks

- The existing real-route integration suite passed against in-memory SQLite D1 and R2 substitutes. It verifies migrations, identity/origin, collection/photo privacy, groups, messaging, reciprocal matching, marketplace flows, unavailable checkout, owner moderation, care custody/quotes/stages, CGC consent, reviews, deletion and valuation provenance.
- QA confirmed all 34 negative groups passed, including concurrent collection writes and offer responses, atomic post throttling, report visibility, durable moderation/owner restoration, receipts/export, legacy collection versioning and server upload boundaries. JPEG metadata after scan boundaries and actual WebP metadata/animation cases also passed.
- The full website TypeScript check passed after the frontend and backend changes (`tsc --noEmit --incremental false`).
- The dense-fixture query-budget checks passed with 202 profiles, 100 groups/listings/conversations and 200 providers/care jobs: social overview used 22 queries (budget 40), workshop overview 20 (budget 40), and an authorized care detail 6 (budget 10). Block, private-cost, private-studio-address and outsider-custody assertions passed alongside these counts. These counts measure isolated SQLite route execution rather than sustained production load.
- `git diff --check` passed. Drizzle schema comparison reported: `No schema changes, nothing to migrate`.

These are isolated implementation and regression checks, not load certification or a claim of full production security review. No live user data was modified by these tests. No browser, native device, simulator or signed mobile release was exercised by this developer role.

## Remaining release gates

The product still needs authorized full-catalog/current Raw and CGC valuation data and cover display rights; merchant onboarding, payments, orders, refunds/disputes and taxes; final operator contacts and policies; moderator/support operations; native account sessions; signed App Store/Play Store builds; and real multi-user browser/device testing. The root agent manages dependency advisory remediation and records unresolved native toolchain findings separately. Public scale pagination, monitoring, backups/recovery and sustained load testing remain operational work. The private preview's supported ChatGPT identity is assumed to be enforced by its hosting platform; direct public-account and platform edge behavior still requires production validation.
